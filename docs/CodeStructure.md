# 代码归属与扩展约定

本文件是源码开发说明；架构评审、设备操作与现场验收记录仍放在项目技术资料库。

## 依赖与状态所有权

`Features → Services → Core` 是主要调用方向。`Design` 放通用显示组件，`App` 负责组装与导航。
Core 不引用 SwiftUI 页面或 ManagementStore；设备协议返回模型或抛出错误，不直接操作界面状态。

- `DeviceStore` 拥有设备库和当前连接，负责未知记录保护、凭据提交、会话修订及访问前置条件。
- `DeviceServiceContext` 固定会话和客户端，跨 await 后复核目标；成功读取后提交原厂密码也经过操作锁。
- `ManagementStore` 拥有前台操作租约、进度、结果与 Live Activity；协议事务委托给对应 Service。
- 页面持有搜索、草稿、选中项和确认弹窗。子组件接收值、Binding 与动作回调，不复制持久化状态。
- `TrafficMonitor` 拥有流量订阅，首页父页面保持其生命周期；连接卡重绘不重新创建网络流。

服务公开方法应注明前置核验、单次提交、回读、取消与结果未知的语义。无确认结果时不得自动重发写入。
原厂能力的密码、UFI/WebSSH 口令和 Mihomo Secret 不合并，不能为了公共接口隐藏凭据差异。

## 新增后端与设备

1. 在 `Core/Backends/<名称>/` 实现实际通信与模型；共享的标准 Mihomo API 保持在 `Core/Mihomo`。
2. 优先实现 `Core/Capabilities` 中适用的小协议。保留 WebSSHAPI 组合接口用于当前兼容，不把专有 shell 塞入所有适配器。
3. 将型号、固件和服务摘要规则放入兼容性声明和适配器，最终写入必须再次验证实际设备。
4. 注册稳定 backendID、客户端工厂、功能清单与验证器。未知 ID 不允许默认使用另一种传输。
5. 在公共用例适用时复用 Services；只有参数、认证或恢复语义不同才新增对应服务。真正专有的 UI 留在后端子目录。
6. 补充契约与迁移测试，再独立记录真实设备读写验收。增加注册项不等于完成设备支持。

现有 UFI 专有模型和 WebSSHAPI 组合是兼容边界；不为消除名称差异而重写已验证协议。
页面层允许根据已声明能力选择专有入口，但不复制固件白名单和通信脚本。

## 测试与历史内容

- `Architecture`：会话、访问控制、数据兼容与注册边界。
- `Services`：业务流程、凭据提交、响应回读与失败语义。
- `Backends`：各协议编码、响应解析、配置与恢复脚本。
- `Diagnostics / Mihomo / Features`：通用诊断、标准控制接口和界面模型。
- `Legacy/Deployment`：历史部署协议与资源回归，不作为正式入口支持声明。
- `Scripts/Tests/F50`：宿主隔离事务测试；使用单元测试导出的生产脚本，不维护第二份测试专用实现。

`build/` 里的历史 ReviewBuild 截图、脚本和编译产物保留原路径，避免破坏验收记录链接；不作为生产源码修改。
`Legacy/Deployment` 保留协议参考代码，但所有构建均不含首次部署载荷；资源缺失时明确拒绝该历史流程。
许可证、桥接 dex 与图标资产保持原资源名称，避免 Bundle 查询及既有文件引用失效。

## Build 52：状态、生命周期与本机数据

- `LatestDeviceRead` 负责同一设备内的读取顺序与取消边界。换会话时 invalidate；过期成功和失败都不能覆盖新状态。
- `DeviceStatusStore.poll` 只保留一个轮询所有者，主动读取期间跳过相应后台采样。
- `visibleDeviceTask` 将读取/流量订阅绑定到页面可见、当前 Tab、前台和设备修订。维护写入不使用此修饰器。
- `PreferredPolicyGroup` 统一首页、快捷指令和小组件操作的常用策略选择。规则模式不猜测多组配置的唯一出口；组失效后重新选择，不偷偷回退到另一业务组。
- `DeviceLocalData` 在最后一条硬件引用移除时清理共享副本。钥匙串或文件删除失败保留连接记录并提示重试；部分清理不宣称完整成功。
- 原厂认证失败仍中断读取；认证成功后保存凭据失败单独警告。相同已存密码不重复写入；设备身份改变始终阻断。
- 后端功能使用显式白名单，禁止 `allCases` 自动放行新功能。`BackendContractTests` 遍历注册项，新后端必须提供测试 fixture。
- Debug 单元测试宿主使用隔离演示偏好，避免模拟器里保存的真实设备引发后台轮询。真机凭据测试仍需显式提供私有配置。

测试分工：`StateConsistencyTests` 覆盖乱序、取消和会话失效；`PreferredPolicyGroupTests` 覆盖任意命名、歧义和失效偏好；
`DeviceLocalDataTests` 覆盖共享引用与凭据保存边界；`BackendContractTests` 覆盖传输失败、未知响应和注册声明。
协议写入、身份变化和回读继续由现有 WebSSH/UFI 专项测试覆盖，不能由通用契约测试替代真机验收。
